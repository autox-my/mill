## 3. Slice `S-04` Scope — Factory Telemetry, Cycle Time & Post-Slice Audit Skill

*(Inspired by `@BHolmesDev`'s 4 factory pillars, scoped tightly for high leverage and YAGNI — single orchestrator recommended since telemetry touches `domain → store → httpapi → httpclient → mcp → observer → cmd/mill` vertically.)*

### Part A: Spending, Model & Cycle-Time Telemetry (`mill` core)
1. **Extend `domain.RunEvent` with optional telemetry fields** (all `omitempty`, backward-compatible defaults `""` / `0`):
   - `Model string` (e.g. `gemini-4-hydrogen`, `claude-sonnet-5-5`)
   - `TokensIn int`
   - `TokensOut int`
   - `CostUSD float64`
2. **Idempotent SQLite migration (`internal/store/sqlite.go`):**
   - `ensureRunTelemetryColumns(db)` via `PRAGMA table_info(run_events)` + `ALTER TABLE run_events ADD COLUMN ...` (matching the proven `ensureSliceRiskColumn` pattern from `S-02`), verified by a legacy-DB migration + double-open test.
   - Persist and read `model`, `tokens_in`, `tokens_out`, `cost_usd` in `RecordRun` and `ListRuns`.
3. **Cycle Time & Model/Harness Breakdown (`domain.StatsSummary`, `internal/store`, `internal/observer`):**
   - Compute **cycle time** for merged slices (`updated_at - created_at` in seconds: average & p50/max) and **total/avg cost & tokens per merged slice**.
   - Add per-`model` (and per-`harness`) breakdown in `StatsSummary` / `observer.Report` (`runs`, `green_rate`, `avg_duration_s`, `total_cost_usd`, `total_tokens`) so future benchmarking across models/harnesses works passively with zero extra setup.
4. **Thread through CLI, HTTP API, HTTP Client, MCP, and Web UI:**
   - `mill run record --model ... --tokens-in ... --tokens-out ... --cost-usd ...`
   - `POST /runs`, `httpclient.RecordRun`, MCP `record_run` tool schema
   - Surface cycle time & cost summary cleanly in `mill stats`, `mill improve --report-only`, and the embedded Web UI (`internal/webui` stats bar / Observer tab).
   - Add `claims/REQ-0015.yml` linked to the new migration, stats, and round-trip tests.

### Part B: Post-Slice Transcript Audit Skill (`.agents/skills/slice-audit/SKILL.md`)
- Create a read-only **Argon post-slice audit skill** that inspects a finished slice's `git diff main...HEAD` + agent `transcript.jsonl` specifically for quality flaws static gates miss:
  1. **Tautological / redundant tests** (tests asserting mocks or trivial getters instead of real behavior/invariants).
  2. **Wasted tool-call loops** (repeated failed commands, re-reading unchanged files, unbatched single-call turns).
  3. **Architecture / boundary drift** (shallow wrappers, leaky abstractions, unnecessary dependencies).
- Outputs a compact scorecard (compatible with the visual Merge Risk format) and feeds recurring patterns into `## Gotchas` in repo skills — read-only, never mutates `claims/` or `.intent/`.
